# iOS HTTPS API 연결 인수 조건

## 목적

현재 앱의 공개 읽기 API는 HTTP에서 동작할 수 있지만, 로그인·계정·관심공연·문의·거래 요청은 HTTPS가 확인되기 전까지 전송하지 않는다. 이 문서는 운영 인프라 담당자가 제공해야 하는 E1 증거를 정의한다.

## 필요한 설정

- 도메인 기반 HTTPS API 원본 한 개를 제공한다.
- 인증서 체인과 기기 신뢰를 확인한다.
- `GET /api/health`는 앱이 기대하는 응답 버전을 반환한다.
- `GET /api/catalog?limit=1`은 실제 공개 카탈로그 응답을 반환한다.
- 인증 요청의 리디렉션은 HTTPS, 같은 원본, 같은 사용자 소유 경로만 허용한다.

## 인수 증거

다음 결과를 민감한 인증 정보 없이 기록한다.

1. HTTPS 원본에서 `GET /api/health`의 2xx 상태와 응답 버전.
2. 같은 원본에서 `GET /api/catalog?limit=1`의 2xx 상태와 카탈로그 형식.
3. HTTP, 다른 원본, 다른 포트, 다른 사용자 경로로의 인증 리디렉션이 거부되는 결과.
4. HTTP 요청에는 `Authorization` 헤더가 없고, HTTPS의 짝지어진 사용자 세션만 인증 요청을 보낼 수 있다는 확인.

## 앱 설정

E1이 준비된 뒤에만 `TICKETGROUND_API_BASE_URL`을 HTTPS 도메인으로 설정한다. HTTP 값을 유지하면 로그인과 사용자별 기능은 HTTPS 필요 안내를 보여 주며 요청을 보내지 않는다.

## 범위 밖

이 문서는 DNS, 인증서, 프록시, 서버 배포를 변경하지 않는다. OAuth 제공자, 결제, 기기 신뢰, 푸시, QR은 별도의 E3 증거가 필요하다.
