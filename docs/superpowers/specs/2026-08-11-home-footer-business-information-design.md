# 홈페이지 푸터 사업자 정보 디자인

## 목표

Ticketground 홈페이지 하단에서 사용자가 사업자와 고객센터 정보를 쉽게 확인할 수 있도록, 기존 `SiteFooter`의 메뉴 영역과 저작권 영역 사이에 법적·연락처 정보 블록을 추가한다.

## 범위

- 홈페이지(`/`)에 표시되는 `SiteFooter`에만 사업자 정보 블록을 노출한다.
- 다른 공개 페이지가 공유하는 기존 푸터 구조와 문구는 변경하지 않는다.
- 기존 브랜드 소개, 정책 링크, 메뉴 열, 저작권 문구는 유지한다.
- 로그인, 인증, 결제 및 백엔드 동작은 변경하지 않는다.

## 정보 구조와 문구

사업자 정보 블록은 기존 주 푸터 영역 아래, 저작권 영역 위에 배치한다.

1. `티켓그라운드 사업자 정보`
   - `주소 : 경기도 고양시 주교동 독곶이길 117`
   - `대표이사 : 윤진영`
   - `사업자등록번호 : 527-44-01245`
2. `고객센터`
   - `이메일 : tigmaster@ticketground.co.kr`

제공된 NOL 참고 화면에서는 굵은 소제목, 차분한 회색 상세 문구, 넉넉한 행간으로 정보 우선순위를 만든다. Ticketground에서는 이 구조만 차용하고 기존 브랜드·색상·타이포그래피는 그대로 유지한다.

## 레이아웃

- 모바일(375~390px): 사업자 정보 다음 고객센터를 세로로 배치한다.
- 태블릿(768px): 충분한 폭이 확보되면 두 정보 묶음을 2열로 전환한다.
- 데스크톱(1280px): 기존 `ticketground-container` 안에서 사업자 정보 열을 넓게, 고객센터 열을 좁게 배치한다.
- 정보 블록 앞뒤에 `border-line` 구분선을 두어 메뉴와 저작권의 의미 계층을 분리한다.
- 주소와 이메일은 작은 화면에서도 가로 스크롤 없이 자연스럽게 줄바꿈한다.

## 디자인 시스템

- 색상: `text-ink`, `text-ink-3`, `text-ink-4`, `border-line`, `bg-background`만 사용한다.
- 타이포그래피: 제목은 기존 푸터의 `text-sm font-black`, 상세 정보는 `text-sm leading-loose` 패턴을 재사용한다.
- 간격: 기존 4px 배수의 Tailwind 간격과 `ticketground-container`를 사용한다.
- 카드, 그림자, 새 색상, 새 모션은 추가하지 않는다.
- 기존 `DESIGN.md` 토큰과 단일 계층 푸터 원칙으로 충분하므로 디자인 토큰은 추가하지 않는다.

## 컴포넌트 설계

- `SiteFooter`에 홈페이지에서만 활성화하는 명시적 boolean prop을 추가한다.
- 사업자 정보 DOM은 의미 있는 제목과 주소·연락처 묶음으로 구성한다.
- 이메일은 `mailto:tigmaster@ticketground.co.kr` 링크로 제공하고 기존 focus ring 패턴을 적용한다.
- 컴포넌트가 1회만 사용하는 정보 블록이므로 별도 전역 primitive를 만들지 않는다.

## 접근성

- 푸터 landmark는 기존 `<footer>` 하나를 유지한다.
- 정보 제목은 읽기 순서를 해치지 않는 heading 요소를 사용한다.
- 이메일 링크는 키보드로 접근 가능하고 가시적 focus ring을 유지한다.
- 색상 대비는 기존 semantic token 조합을 따른다.

## 검증

- 문구 네 항목이 정확하게 렌더링되는 회귀 테스트를 추가한다.
- 홈페이지에서만 정보 블록이 보이고 다른 공유 푸터 화면에는 나타나지 않는지 확인한다.
- 375px, 768px, 1280px 실제 Chrome 화면을 캡처해 줄바꿈, 여백, 구분선, CJK 표기를 검증한다.
- 변경 파일 lint, TypeScript, 프로덕션 빌드와 관련 테스트를 실행한다.
- PR에서 독립 코드 리뷰와 시각 QA를 거쳐 미해결 스레드와 필수 CI가 모두 0/green일 때 병합한다.
